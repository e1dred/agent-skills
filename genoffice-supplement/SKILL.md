# GenOffice supplement

**Scope rule (strict):** this skill holds only things GenOffice's own bundled skills do not provide. It never copies or restates
a GenOffice-provided skill (its generated `genoffice` skill, the ~45 recommended app skills). Read those first; this adds
what running the app showed. Tested on GenOffice 0.12.117 (Linux AppImage), CLI and MCP, headless.

GenOffice has six editors: Docs, Sheets, Slides, Markdown, HTML and PDF. The Docs (.docx), Sheets (.xlsx) and Slides (.pptx ops and the page-spec build) are covered, plus the conversions that reach the Markdown, HTML and PDF editors. The live editor (`open`, `selection`, writes to an open file) is covered too.

## Word-op sweep, 2026-10-27, GenOffice 0.12.117 (headless CLI `genoffice docs apply`)
Method (scripts in `tools/`, re-run with `tools/run_sweeps.sh`): fresh copy of a 9-block docx per op, apply, then read back with `docs read` flags, unzip the XML, and render (`genoffice render x.docx --out dir`, one PNG per page) and look.

Status "ok" only means the op was accepted. Check the XML or the render.

Verified (XML and/or render): setFont (bold, colour, size, family; link), setMatchedFont (text -> run-level bold+highlight), setParagraphFormat (jc, line, firstLine, spacing, shading, borders "tb", tabs with leader), setHeadingLevel, findReplace, deleteBlocks, moveBlocks, setList/clearList, insertToc (TOC field, entries listed, NO page numbers in render; Word computes them on open), insertField SEQ/DATE/MERGEFIELD/REF, insertBookmark, updateFields, table row/column insert/delete, mergeTableCells/splitTableCell, setTableCellFormat (fill, vAlign, borders), applyStyle, insert_content (h2, p, pre, blockquote, formula), replace_blocks, insert_image, insert_picture (floating, wrapSquare, alt text), setImageProperties, insert_text_box, insert_chart/edit_chart (native chart part + embedded workbook), set_header_footer ({PAGE}/{NUMPAGES} work; first/even views set titlePg/evenAndOddHeaders), set_page_setup (paper, landscape, margins, 2 columns, pageNumberStart), insert_section_break, set_watermark (rendered diagonal), define_style, add/reply/resolve/delete comment (threads, done flag), insert_footnote/endnote, set_properties (core+custom), wrap/unwrap_content_control, --track (author, ins/del revisions), accept_changes/reject_changes (selector by author/type/all), `docs compare` (redline with revisions).

## Traps (each one tripped the sweep)
- Op field names differ from what you guess: `moveBlocks` takes `blockIndexes` (no `target`); `setList` takes `kind: "bullet"|"number"` (not `type`). Rejections name the allowed fields and the whole batch is atomic: nothing applied.
- Things defined or created earlier in a batch are NOT visible to later ops of the same batch for: `define_style` type table then `setTableStyle`; `wrap_content_control` then `unwrap_content_control`. Split into two `apply` calls. (define_style paragraph then applyStyle in one batch works.)
- `define_style` for a new style needs paragraph or run formatting (or basedOn); basedOn must exist in the document. A new docx has no table styles (`tableStyles: []`), so create one with a run property and apply it in a second call.
- `setTableCellFormat` fill does not change text colour: a dark header fill keeps black text. Set white text separately (setFont on that block does not reach table cells in my sweep; not yet tested how).
- `insert_text_box` default anchor is the paragraph, so x/y count from the margin, not the page edge: x 15cm + 4cm wide ran off the right side. Use `anchor:"page"` for page coordinates. insert_picture needs `float.anchor:"page"` the same way.
- Comment ids are small positional strings ("1", "2"); revision ids ("r1"...) are positional and change after every edit, so re-read before accept/reject.
- Reject-all restored the original text; accept with type filter leaves the other revisions pending.
- Table merge concatenates cell text as separate paragraphs; split keeps text in the top-left cell.
- Watermark is heavy at opacity 0.3 with a large size; use about 0.15 for body-text legibility.

## Not yet tested
setFont null (clear), partial-selection edits, setImageProperties on a floating picture, insert_content formula render, insertField IF/PAGEREF, docs apply on a file open in the app (needs --force), `--dry-run`, `--best-effort`, live `open`/`selection`, and comparison with WordCraft/ONLYOFFICE styles.


## Sheets sweep (`genoffice sheet apply`), 2026-10-27, GenOffice 0.12.117 (headless)
Method as for Docs: a 7-row sales table (text, numbers, dates; made with `genoffice create --type xlsx --from base.csv --header`, which freezes row 1 and adds an AutoFilter) copied per case, apply, then `sheet read --range` (values, formulas, `features`) plus the XML (`unzip -p x.xlsx xl/worksheets/sheet1.xml`) and one render.
Verified (value or XML read back): set_cell (`type:"text"` keeps "=1+1" as literal text), set_formula (SUMIFS, IFERROR+VLOOKUP, XLOOKUP, TEXTJOIN computed and cached), set_range, clear_cell/clear_range, fill_range (formula copies adjust: F2:F7), copy_range (also `filterColumn`/`filterValues`: copied only the North rows), move_range, find_replace, sort_range (desc by Qty with `hasHeader`), format_range (fill, font, bold, alignment, `$#,##0.00`, `yyyy-mm-dd` as real number formats), add_conditional_format (number, colorScale, dataBar, text, duplicate, top10, formula; 6 rules stacked) and clear_conditional_formats, set_data_validation (list, numberBetween, listRef, dateBetween, checkbox, formula), merge/unmerge, row height and column width, hidden rows and columns, freeze, filter and `clear_filter`, set_page_setup (landscape, A4, fit-to-page, narrow margins, print area and titles as defined names, header, footer, row break, gridlines), hyperlink and note, defined names, add_table, add_pivot, add_chart (column, pie, line), edit_chart, add_image, add_shape (roundRect, textbox), add_sparkline (XML written), insert/delete rows and columns (later ops use the shifted grid), add/rename/duplicate/move/hide/delete sheet.
Pivots work and compute real numbers: rows Region by columns Product with a sum gave North 10/7, South 3/4, East 12/9 and grand totals 45; `showDataAs:"percentOfTotal"`, an `average`, a label filter, and a month grouping of a date row field (Jan 10, Feb 11, Mar 15, Apr 9) all matched the data.

Traps found:
- **`protect_sheet` ignores `password` and `allow`** (headless): the XML only had `sheet="1" objects="1" scenarios="1"`, no password hash and no allowed-action attributes. Do not rely on it for protection.
- **Formulas the engine lacks are stored without a cached value:** `FILTER` was written as an array formula with no `<v>`, and `sheet read` showed `#NAME?`; Excel computes it on open. `XLOOKUP`, `TEXTJOIN`, `SUMIFS` and `VLOOKUP` were cached correctly.
- `convert_to_values` refuses a batch that also edits the cells it converts ("earlier ops in this batch edit cells"): write the formulas in one `apply`, convert in the next.
- `add_table` fails ("overlaps the sheet…") on a range that has the sheet's AutoFilter: `clear_filter` in a first `apply`, then `add_table`. Same split rule as the Docs ops (later ops in one batch cannot see some earlier ones): also `duplicate_sheet` then `move_sheet` on the copy, and a new sheet then `add_pivot` into it.
- `move_sheet` `position` is 1-based (0 is rejected). `add_pivot` `sourceRange` takes plain `A1:E7` (a `base!A1:E7` prefix fails the pattern; name the sheet with `sheet`), and `filters`/`groupings` fields must also be row or column fields of the pivot.
- `add_chart` needs a numeric column in `dataRange` ("needs at least one numeric column"); `edit_chart`'s `chartPath` accepted `xl/charts/chart1.xml` and changed the title and type even though `sheet read` calls the chart `visual-1`.
- Rendered (`genoffice render`): fills, fonts, colour scale, chart and shape appear; **data bars and sparklines did not show in the render** (their XML exists; not checked in Excel or another app). Wide content splits across pages when printed.
- Dates from the CSV import arrive as real dates (serial numbers with a date format).
- Editor-only ops (`refresh_pivot`, table row and column edits, `edit_shape`, `delete_visual`) answer "not available headless (use the GenOffice app)".

## Slides sweep (`genoffice slides apply`), 2026-10-27, GenOffice 0.12.117 (headless)
Method: a 2-slide deck made with `genoffice create --type pptx --ops` (a text box, a filled rectangle and an ellipse on slide 0, an empty slide 1), a copy per case, `slides apply`, then `slides read --full`, the XML, and renders of 14 results on one contact sheet. Insert ops cannot reference the element they create in the same batch (ids come back in `created`; read the slide to get them), so editing a new table is two `apply` calls.
Verified (read back, XML or render): setText (runs, alignment, bullet and level; unstyled runs inherit the old run's size), setFont, setParagraphFormat, insertEquation (a native `m:oMathPara`), setFill (gradient stops with angle; `"none"` clears), setStroke (null removes), setTransform (box and rotation), flipElements and reorderElement, setShapeGeometry (hexagon) and setShapeAdjust, setShapeCustomGeometry (a triangle path), setTextAnchor and setTextBodyProps (vertical text, insets), setEffects (shadow, glow and soft edge all written and the shadow and blur rendered), setLink (url and slide jump), alignElements and distributeElements, groupElements, deleteElement, addElement (roundRect with adjustments, star5, lineArrow), addConnector (elbow, glued, arrow end), addTable and the table ops (setTableCell, tableMerge, tableStructure, row height, column width, anchor, style), addChart (bar with colours, pie, comboBarLine), addSmartArt (process: three chevrons rendered), duplicateSlide, addSlideWithLayout, moveSlide, setBackground (solid and gradient), setHidden (`show="0"`), setTransition (fade) with setAdvanceTime (`advTm`), addAnimation (preset ids 10 and 23, five timeline parts), setNotes and addComment (notes slide, comment part and author part), findReplace across the deck, setSlideSize (elements rescaled in proportion: x 914400 became 685800 going from 16:9 to 4:3), applyHeaderFooter (a footer and slide number shape on every slide), applyTheme (accent1 and the two fonts in `theme1.xml`), setSections (`p14:section`).
Designed-deck path: `genoffice create --type pptx --spec page.json` built a one-page deck from a 1280x720 px spec (text and shape elements) and answered with the next-step commands. `slides audit` reports `out_of_bounds` and `text_overflow` as errors with a ready `setTransform` suggestion (a rectangle 190 px past the right edge; text 477 px over its box), and it does NOT report one shape sitting on top of another. Its metrics are heuristic glyph widths.

Traps found:
- Field shapes differ from what you guess: `setFont` takes `font:{fontFamily,fontSizePt,bold,italic,underline,strike,color}` and `setParagraphFormat` takes `format:{align,bullet,lineSpacingPct,spaceBeforePt,spaceAfterPt}` (flat fields are rejected with a usage message); `addElement` text runs use `fontSize` (pt) but `setFont` uses `fontSizePt`.
- `setTableStyle` with `shadingColor` shades the WHOLE table (first row included) and keeps black text: on a dark colour the text is nearly unreadable. Set a light shade, or set white text on the header row with setTableCell/setFont.
- `tableStructure` `insert-col` at `index` equal to the current column count fails with "merges crossing the boundary?"; use the index of an existing column (2 for a 3-column table). Do structure ops before merges.
- `addChart` ignores `colorScheme` for pie charts (series colours came out default orange and blue); bar colours applied.
- Elements and ids: `slides read` ids (`e_*`) are the targets; a created element's temporary id is not usable in the same batch.
- Deck ops such as `applyHeaderFooter` add the footer and number as real shapes on each slide (they show up in `slides read`), and `setSlideSize` rescales every element.

## Markdown, HTML and PDF through the CLI (2026-10-27, GenOffice 0.12.117, headless)
The CLI has no edit ops for Markdown, HTML or PDF (`genoffice guide` lists docs, sheets and slides only). What exists: `convert`, `create --type docx|pdf --from`, `pdf read`, and `merge`. Supported routes (from `convert --help`): md to docx, html or pdf; html to pdf or docx; docx to md, html or pdf; pdf to docx, pptx, xlsx, md or html; csv to xlsx or pdf. Anything else (html to md, for example) answers `unsupported` with the list of routes.
Method: one Markdown file with a heading, bold/italic/strike/inline code/link, a nested list and a numbered list, a block quote, a right- and centre-aligned table, a fenced code block, inline math, a footnote, a picture, a rule and CJK/accented text, converted along every route and read back (`docs read`, the XML, `pdf read`, renders).
- **md to html** is faithful: real `h1/h2`, `strong/em/s/code`, nested `ul`, `blockquote`, a table with `text-align` on cells, `<pre><code class="language-python">`, an `<img>`, `<hr>`. Extras: a `div.tableWrapper` and `colgroup` around tables, `target/rel` on links, math as an empty `<span data-latex="E=mc^2" data-type="inline-math">`, and the footnote as a `[^1]` superscript plus a definition div.
- **md to pdf** is the best-looking route (GitHub-like styling, shaded code block, styled table, real typeset math). The footnote is NOT a footnote: the `[^1]` marker stays in the text and the definition lands as a line on an extra last page.
- **md to docx** keeps headings, lists (nested), the table (but column alignment is lost), a code block (as Consolas paragraphs, not a code style), the picture (relative path resolved from the .md), the block quote (left border and indent, line break kept as `w:br`). It does NOT convert math (`$E=mc^2$` stays literal) or footnotes (`[^1]` and the definition stay as plain paragraphs, not Word footnotes). The horizontal rule is a bottom-border paragraph.
- **docx to md** loses: nested list levels (flattened), fenced code and inline code backticks, the picture (dropped), table alignment, the rule, and it backslash-escapes `$` and `[^1]`. Headings, bold/italic/strike, links, simple tables and block quotes survive.
- **pdf to docx/md/html/xlsx** work on a text PDF without the app (`pdf read --full` returns the title, creator, page size and per-page text). Structure is guessed: headings come back as plain or bold paragraphs (no heading levels), bullets lose their markers and nest nowhere, tables ARE recognised as tables (docx and md), pictures survive in docx but are dropped from md (warning `images_dropped`), math is linearised (`E = mc2`). **pdf to xlsx** lays text out per page as cells on a sheet named "Page 1" (not a table of data).
- **Traps:** `convert x.html --to docx` HANGS (no output, no timeout; killed at 110 s) whenever the HTML contains any `<img>` (relative path, `file://` and `data:` URLs all tried), while the same file without the image takes about 7 s: remove the images or build the docx with `create --type docx --from x.html` (about 1 s; it ignores `<img>`, add pictures afterwards with `docs apply insert_image`). Do not feed `create --from html` the HTML that md to html produced: the `tableWrapper` div, `colgroup` and `<p>` inside cells made the table collapse into one paragraph ("RegionSalesShareNorth1040%…"), and the math span disappeared; it also set the PDF's table with no borders. `create --type pdf --from x.html` rendered the HTML in a serif, plain style (no math, borderless table), unlike md to pdf.
- Progress lines (`page 1/2`, `starting GenOffice for pdf export`) go to stderr, so `--json` output stays parseable on stdout; merge them with `2>&1` and a JSON parse fails.
- Conversions that need the app (`pdf` and `html` exports, a hidden GenOffice process) take a few seconds each; text-only routes (`pdf read`, `create --from`) are instant.

## Live editor: `open`, `selection`, writing to a file that is open (2026-10-27, GenOffice 0.12.117, checked with the user watching the window and a screenshot)
Needs the GenOffice app running (the CLI starts it if not); `~/.config/GenOffice/open-documents.json` lists the open files and `control.json` holds the control socket and token. Each file opens in its own tab.
- **`genoffice open FILE [target]`** opens the file and selects a spot for the user: `--block n` (docx, 0-based as in `docs read`), `--range B2:C4` / `--sheet` (xlsx), `--slide n --el e_...` (pptx, ids from `slides read`), `--page n` (pdf, 1-based). All four put the selection where asked and the tab in front.
- **`genoffice selection FILE --json`** is the user's pointer ("this one", "here"). Verified: docx `blocks [3,3]` with the paragraph text (and after the user resized a table, `block 6`, `collapsed:true`, empty text); xlsx the range with its values (`base!B2:C4`); pptx `slide 0, elements [e_...]`; pdf `page 2` only. Read it only after the file has finished loading: asked about 3 seconds after reopening a spreadsheet it returned `S27` (the user had clicked) instead of the range just opened; 8 seconds later it returned the right range.
- **Writing to an open file:** `docs|sheet|slides apply` refuses with `file_open_in_gui` (the message says close the tab or pass `--force`); `--out` to another path always works. With `--force` the file on disk is written, but the window does not reliably show it:
  - xlsx: a forced `set_cell` and a gold fill did NOT appear in the open tab, even with that tab in front and after a plain `open --range` on the same file. Only after the user closed the tab and `open` reopened the file did the new cells and the fill show.
  - docx: after a forced `setFont` (bold plus colour C00000) the user saw the paragraph change to bold but not red (the headless render and the XML show both bold and red). Not explained; treat a forced write into an open document as unreliable and have the user close the tab and reopen.
  - The user's own unsaved resize of a table in the window was still there after the forced write, so the window seems to keep its own state; the app's message warns that the editor may overwrite your change on its next save. Do not force-write a file the user is editing.
- **Recipe for working with the user in the app:** copy the file to a scratch folder, `open` it at the spot you mean, ask the user to select or click, read `selection`, make the change with `--out` to a new file, then `open` that file. Avoid `--force`.
- Screenshots the user takes are the fastest way to check what the window shows (the folder path they give may contain a typo: list the folder first).

## Docs gaps closed (2026-10-27, GenOffice 0.12.117, headless)
- **Batch flags (`docs apply`):** `--dry-run` validates and prints the plan without writing; with an unknown op it returns `unknown_op` and the list of supported ops (nothing written). `--best-effort` applied 2 of 3 ops and wrote the file (status `partial`, `detail.failures` names the bad op and why); `--stop-on-error` applied the first op, failed the second and skipped the third (`1 failed, 1 skipped`). The default is all or nothing.
- **Clearing font settings:** `setFont` with `null` removes a property (`color`, `fontSize` and `fontFamily` set to null left only `<w:b/>`); fields you leave out stay as they were.
- **Coloured borders, letter-spacing and bullet colour cannot be set with ops** (`setParagraphFormat borders` takes only the letters "tblr", unknown fields such as `borderColor` are rejected). **Workaround that works:** after the last `apply`, rewrite the .docx zip and patch `word/styles.xml` (insert `<w:pBdr>` with colour, size and space into the style's `w:pPr` before `w:shd/tabs/spacing/ind/jc`, and `<w:spacing w:val="N"/>` before `w:sz` in its `w:rPr` for letter-spacing) and `word/numbering.xml` (a `<w:color>` in the bullet level's `w:rPr`). `build_genoffice.py` does this in `post_process`. Result, rendered against WordCraft: the professional (navy title and heading rules, spaced caps), elegant (burgundy hairlines), creative (teal rules), stylish (gold bar) and traditional (title rule) styles now match, and bullets take the accent colour. Order matters in OOXML, which is why the insert points are fixed.
- **Résumé and CV kinds** now build too (`build_genoffice.py STYLE resume|cv /abs/out.docx`): both consist only of paragraphs, so the same path works. Right-aligned dates come from a style tab stop (`define_style paragraph.tabs: [{"pos":"506pt","align":"right"}]`) plus a tab in the text; **in the HTML input a tab character is lost, it must be written `<span data-tab></span>`**. Compared page 1 with WordCraft's version for the professional style: the same layout, headings, rules, bullets and right-aligned dates (education dates are not bold in the GenOffice version).
- **Not done:** partial-selection edits (they need a selection made in the app).

## All eight styles x doc, report, resume and cv against WordCraft (2026-10-27, A4, same renderer)
`build_genoffice.py` and `styles/build_wordcraft.py` were run for every style and kind (32 pairs) and every page was rendered with `genoffice render` and compared: page count (all 32 pairs equal) and the mean absolute pixel difference of a 300x424 greyscale page (0 = identical; text anti-aliasing alone gives about 2 to 3).
Mean page difference (higher = less alike): doc 2.4 (clean) to 8.3 (professional, one page of tighter text); resume 2.8 (modern) to 5.9; cv 4.0 (modern) to 8.0 (academic, creative); report 6.1 (clean) to 13.7 (stylish). Overall 6.1. Clean, modern and the résumés match closely; the report kind differs most because of table details.
What still differs, seen on side-by-side images:
- **Report tables:** the fact-sheet and KPI cells are left-aligned in GenOffice's version (WordCraft centres the KPI row): there is no op to align one cell's paragraph, only the whole table (`setParagraphFormat` on the table block). Cell text sizes are a little larger, columns wrap earlier ("Community Garden Program" wrapped in the academic style) and rows are slightly taller, so a table can slip across a page break (the risks table lost its last row to page 2 in two styles).
- **Bullets:** the bullet indent is wider than WordCraft's in every style.
- **Header text** is centred (no alignment op), where the plan wants it right-aligned.
Bug found while comparing: **`define_style` drops a zero first-line indent**, so in the academic style (Normal has a 0.5 in first-line indent) every style based on Normal (headings, bullets, table text, captions) inherited it and looked indented. `post_process` now writes `<w:ind w:firstLine="0"/>` into those styles.
Other builder additions: report tables (per-cell fills, status colours, column widths from the plan, header row, optional grid, cell paragraph spacing set on the whole table) through `setTableCellFormat`/`setMatchedFont`; cell paragraphs otherwise take Normal's spacing, which made every table row far too tall.

## Style rebuild: `modern` doc via GenOffice vs WordCraft vs ONLYOFFICE (2026-10-27)
Builder: `build_genoffice.py` in this folder (imports `../styles/plan.py` read-only, so the same plan feeds all three apps). Run: `PYTHONDONTWRITEBYTECODE=1 python3 build_genoffice.py modern doc /abs/out.docx --paper=a4 --page-numbers=bottom-center`. Handles block types p/heading/bullets/table/figure caption text of kind doc; figure picture, footnote, merged title row, columns, header text are not done yet.
All three docx files were rendered with the same renderer (`genoffice render`) and compared side by side (WordCraft: `wordcraft-cli run --script job.json`).
Result: title, headings, body, subtitle, margins, header-row fill, page number and table borders match. Differences left in GenOffice's version:
- Quote left bar and heading rules: `define_style` has no borders. `setParagraphFormat borders` takes only "tblr" letters and writes a thin auto-coloured line (sz 4, colour auto), so no teal bar and no coloured heading rule.
- Bullet colour: stays black (WordCraft and ONLYOFFICE give teal bullets); bullet indent is larger.
- Text looks slightly larger than in the other two at the same point sizes (not investigated).
Traps from this build:
- `define_style` lengths (spaceBefore/After, indents) are POINTS; twips (pt*20) made 20x gaps and an 8-page document. `setParagraphFormat` lengths are twips. Different units in two ops of the same guide.
- `insert_content` HTML lists/tables get block indexes: a `<ul>` makes one block per `<li>`, a table is one block.
- A table header row needs white text set per cell: `setMatchedFont {text: "<cell text>", color, bold, target: table block}` works inside table cells.
- Create the docx from HTML (`genoffice create --type docx --from in.html`), then define_style in one apply and applyStyle in a second apply.

## All eight styles, doc kind, GenOffice vs WordCraft (2026-10-27, A4, rendered with the same renderer)
