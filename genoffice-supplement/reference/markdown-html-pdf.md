# GenOffice supplement reference: Markdown, HTML and PDF

Part of the genoffice-supplement skill. The short front page is `../SKILL.md`; the sections below are unchanged from the single-file guide.

## Markdown, HTML and PDF through the CLI (2026-10-27, GenOffice 0.12.117, headless)
The CLI has no edit ops for Markdown, HTML or PDF (`genoffice guide` lists docs, sheets and slides only). What exists: `convert`, `create --type docx|pdf --from`, `pdf read`, and `merge`. Supported routes (from `convert --help`): md to docx, html or pdf; html to pdf or docx; docx to md, html or pdf; pdf to docx, pptx, xlsx, md or html; csv to xlsx or pdf. Anything else (html to md, for example) answers `unsupported` with the list of routes.
Method: one Markdown file with a heading, bold/italic/strike/inline code/link, a nested list and a numbered list, a block quote, a right- and centre-aligned table, a fenced code block, inline math, a footnote, a picture, a rule and CJK/accented text, converted along every route and read back (`docs read`, the XML, `pdf read`, renders).
- **md to html** is faithful: real `h1/h2`, `strong/em/s/code`, nested `ul`, `blockquote`, a table with `text-align` on cells, `<pre><code class="language-python">`, an `<img>`, `<hr>`. Extras: a `div.tableWrapper` and `colgroup` around tables, `target/rel` on links, math as an empty `<span data-latex="E=mc^2" data-type="inline-math">`, and the footnote as a `[^1]` superscript plus a definition div.
- **md to pdf** is the best-looking route (GitHub-like styling, shaded code block, styled table, real typeset math). The footnote is NOT a footnote: the `[^1]` marker stays in the text and the definition lands as a line on an extra last page.
- **md to docx** keeps headings, lists (nested), the table (but column alignment is lost), a code block (as Consolas paragraphs, not a code style), the picture (relative path resolved from the .md), the block quote (left border and indent, line break kept as `w:br`). It does NOT convert math (`$E=mc^2$` stays literal) or footnotes (`[^1]` and the definition stay as plain paragraphs, not Word footnotes). The horizontal rule is a bottom-border paragraph.
- **docx to md** loses: nested list levels (flattened), fenced code and inline code backticks, the picture (dropped), table alignment, the rule, and it backslash-escapes `$` and `[^1]`. Headings, bold/italic/strike, links, simple tables and block quotes survive.
- **pdf to docx/md/html/xlsx** work on a text PDF without the app (`pdf read --full` returns the title, creator, page size and per-page text). Structure is guessed: headings come back as plain or bold paragraphs (no heading levels), bullets lose their markers and nest nowhere, tables ARE recognised as tables (docx and md), pictures survive in docx but are dropped from md (warning `images_dropped`), math is linearised (`E = mc2`). **pdf to xlsx** lays text out per page as cells on a sheet named "Page 1" (not a table of data).
- **Traps:** `convert x.html --to docx` HANGS (no output, no timeout; killed at 110 s) whenever the HTML contains any `<img>` (relative path, `file://` and `data:` URLs all tried), while the same file without the image takes about 7 s: remove the images or build the docx with `create --type docx --from x.html` (about 1 s; it ignores `<img>`, add pictures afterwards with `docs apply insert_image`). Do not feed `create --from html` the HTML that md to html produced: the `tableWrapper` div, `colgroup` and `<p>` inside cells made the table collapse into one paragraph ("RegionSalesShareNorth1040%…"), and the math span disappeared; it also set the PDF's table with no borders. `create --type pdf --from x.html` rendered the HTML in a serif, plain style (no math, borderless table), unlike md to pdf.
- Progress lines (`page 1/2`, `starting GenOffice for pdf export`) go to stderr, so `--json` output stays parseable on stdout; merge them with `2>&1` and a JSON parse fails.
- Conversions that need the app (`pdf` and `html` exports, a hidden GenOffice process) take a few seconds each; text-only routes (`pdf read`, `create --from`) are instant.
