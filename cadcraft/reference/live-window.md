# CadCraft reference: live window

Part of the cadcraft skill. The short front page is `../SKILL.md`; the sections below are unchanged from the single-file guide.

## Live window
- To refresh a drawing the file on disk changed: `execute {"command":"close","params":{"index":N}}` (a clean document closes without a prompt) and `open` it again; `open` alone adds a second copy.
- `open {"path":"…dxf"}` → `{entities,index,warnings}` opened the drawing as a new document next to the user's empty `Drawing1` (nothing replaced). `execute {"command":"zoom","params":{"mode":"extents"}}` → null.
- **`screenshot` answers "no frame was presented (screen locked or window hidden)" when the window is not visible**; the offscreen `ui.render` renders only the drawing, not the UI. Ask the user to unlock the screen and bring the window forward before any UI test.

> **Re-checked 2026-11-03 on 0.17.0:** the MCP bridge (`cadcraft-cli mcp --connect 127.0.0.1:47827`, `tools/ccmcp.py`) answered `inspect_drawing`, ran `execute line` (the entity count went from none to one line) and `execute undo` (`undone:["Line"]`, back to none). The rounds below were run on 0.13.0.

## Round 6: live window (2026-10-26, app 0.13.0 on port 47827, screen unlocked, screenshots looked at)
- `screenshot {"path"}` now works: 2572×1894 PNG of the whole window (toolsets, layers and properties panels, command line, status bar); the window is 1286×947 logical px (2× scale). `render {"window":[[x0,y0],[x1,y1]]}` returns only the drawing. `ui_inspect` gives documents (index, dirty, entity count), prompt/running command, selection, all drafting settings (OSMODE 4133, ORTHOMODE, polar), the view (`center`, `height`) and the docking layout.
- **Interactive drawing by clicks works:** `command_line {"text":"LINE"}` starts the command (the prompt is in the result's `prompt`), then `ui_click {"x","y"}` in WORLD coordinates answers each point prompt (a polyline of 3 clicks, a circle centre then `command_line "8"` for the radius, a rectangle by two corners, DIMLINEAR by three clicks, OFFSET: `5`, click the object, click the side, empty line to exit). Typed answers `@10<90`, `@5,5`, `C` (close), numbers and an empty string (Enter / finish) all work through `command_line`. `ui_click {"button":"right"}` is Enter; with no command running, Enter or right-click REPEATS the last command (this started an unwanted DIMLINEAR in my test): end with `cancel {}` instead.
- **Selection by click:** a click on an object selects it (`ui_inspect.session.selection`, picked-first then `MOVE` worked on it), two clicks on empty space left-to-right make a window selection, a click on empty space does not clear it; ERASE with a window drag erased all four objects and `undo` restored them.
- **Not applied to `ui_click`:** object snap (a click at (60.4,20.3) beside an endpoint stayed 60.4,20.3), and ORTHOMODE (set with `setvar`): clicks are exact world points. For exact geometry use coordinates or the JSON commands, not snapping.
- **`ui_click` is canvas-only:** screen-space clicks on toolset icons, menus and panels did nothing useful, and `execute` with an empty `params` never opens dialogs (`options` returns the settings JSON, `plot` returns base64 PDF data, `dimstyle`/`style` demand a `name`). So panels and dialogs cannot be driven; use the JSON commands.
- Every `new_drawing` adds a tab (Drawing2…4 left open and unsaved in the user's window). `inspect_drawing` and `query_entities` read the ACTIVE document.

## Round 9: a real drawing in the live window (2026-10-26; screenshots looked at)
- `open {"path"}` loaded a 285-entity schematic as a new tab (`{entities, index, warnings:[]}`) and a screenshot after `zoom extents` showed it complete: frame, wires in net colours, symbols, text, legend. Read-only actions (zoom, `find_text`, `dist` by clicks, `view save/delete`) still mark the tab modified (`*`): **never save** a user's file you opened for inspection; do edits on a COPY opened as another tab (`open` the copy).
- **`find_text` filters with `contains`** (`{"contains":"NOTE 1"}`, case-insensitive substring, returns `at`, `height`, `layer`, `handle`); `{"text":…}` is ignored and lists all 114 texts. Zoom to a found text with `zoom {"mode":"window","p1","p2"}` around `at`.
- **Click selection in a dense drawing:** a click within the pick box of ANY object selects that object instead of starting a window, so two "empty" corner clicks often selected the frame polyline only. Select regions with `execute select {"window":[[x0,y0],[x1,y1]]}` (returns the handles; a window takes only objects fully inside) and then run the command: `command_line MOVE`, `ui_click` base point, `ui_click` target moved the two selected objects by exactly (0,-10), and `undo` restored them (verified by text position).
- `DIST` by two clicks reports in the command history (`Distance = 36.0555, Angle in XY Plane = 326…`), the same text as the JSON `dist`.
