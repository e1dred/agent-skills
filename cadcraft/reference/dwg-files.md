# CadCraft reference: DWG files from other programs

Part of the cadcraft skill. The short front page is `../SKILL.md`; the sections below are unchanged from the single-file guide.

## Round 10: a real AutoCAD DWG from another program (2026-10-26, 0.13.0 = latest GitHub release v0.13.0 of 25 Oct; renders looked at)
- **Version check:** `cadcraft.appimage --version` opens the GUI, so compare the CLI (`cadcraft-cli --version`) with https://github.com/storytold/cadcraft/releases/latest (the page names the tag, e.g. v0.13.0, and its date). Both were 0.13.0.
- **A 2007-format (AC1021) architectural DWG with 1380 entities** (1178 lines, 56 arcs, 14 hatches, 28 dimensions, 36 multileaders, 16 block references, 9 block definitions, 49 layers, one A-size paper layout with 4 viewports) opened with no warnings and `skipped: 0`, converted to PDF in 0.3 s (letter page; the layout exports at ARCH D, 2592×1728 pt with `exportpdf {"layout":…}`), and DWG → DWG → DXF kept every entity count. The renders showed the sections, stair hatches, dimensions, multileader text, title block and four viewports correctly, in both the exported PDF and the live window's PAPER view (`layout {"option":"set","name":…}` then `zoom extents`).
- **Reading it:** `texts` returns MText and multileader text with layer, height and style; `entities {"type":"Multileader"}` gives arrow size, dogleg, landing, leader points and the text contents; `entities {"type":"Dimension"}` gives `measurement` and per-dimension overrides (scale 48, text height, arrow size); `scalelistedit {}` lists the drawing's scales; `dataextraction {"file":"x.csv"}` produced a title-block table (columns Count, Name, then every attribute tag: REV, DATE, PROJECT_NAME, …) from the blocks in model and paper space; `audit` found one zero-length line (not fixed unless `fix:true`); `purge` removed an unreferenced dynamic block and 6 layers.
- **Dynamic blocks (read and edit, verified):** inserts of dynamic blocks are anonymous (`*B9`) and live in the layout's space, so `layout set` first, then `blocks.reference {"handle":"23E8"}` (definition "Drawing Title", property `Distance` 1.2747), `blocks.reference.grips`, `blocks.reference.set {"handle","name":"Distance","value":20}` (end point moved to x+20) and `blocks.reference.grip {"handle","node":80,"part":"end","to":[30,9]}` (distance 25.1583). `blocks.dynamic {"name":"Drawing Title"}` described the parameter (linear distance) and its stretch action; give it the definition name, not `*B9`.
- Entities in layout (paper) space are only visible to `entities` after `layout set`; block references there: Rev, title and the four viewport-related anonymous blocks.

## Round 11: save versions and the last open items (2026-10-26, real AutoCAD DWG as the source)
- **`saveas {"path","version":2000|2004|2007|2010|2013|2018,"binary":bool}`** (also `document.bytes`) writes DWG or DXF in each release; every file reopened in `info` with the right header (AC1015, AC1018, AC1021, AC1024, AC1027, AC1032) and the same 49 layers, 28 dimensions and 14 hatches, `skipped: 0`. **2007 and later keep all 36 multileaders; 2000 and 2004 cannot store them, so they come back as 36 `Leader` objects plus 33 extra `MText`** (1403 entities instead of 1367, 19 block references instead of 16): save as 2007+ unless the recipient needs R2000/R2004. `binary:true` gave a valid "AutoCAD Binary DXF" (1367 entities). Reading older/newer DWG written by other programs: only the 2007 file from AutoCAD was available; the CadCraft-written files of all six versions read back correctly.
- **Dynamic blocks cannot be AUTHORED by commands:** the command list has no parameter/action/visibility-state commands (only `blocks.dynamic`, `blocks.reference`, `.set`, `.grips`, `.grip`, `bedit`, `bsave`, `bsaveas`, `bclose`); the block-editor palette is UI that `ui_click` (canvas only) cannot drive. Read and edit existing dynamic blocks (Round 10), and create plain blocks with `block`/`bedit`.
- **Second CadCraft version:** none exists (v0.13.0 is the latest release); when one appears: extract the new CLI, diff `cadcraft-cli commands`, re-run `tools/ccrun.py` samples, relabel the sections.

## Round 12: two more AutoCAD DWGs, 2010 format (2026-10-26; renders looked at)
- **A parametric imperial mechanical part (AC1024, 88 entities: 56 lines, 17 dimensions, 8 circles, 7 arcs, CENTER linetype, dimstyle `MEP`, LUNITS 4 architectural, INSUNITS 1 inches)** opened with `skipped: 0` and rendered as plan, side and top views with centre lines. Its dimensions are AutoCAD dimensional constraints: CadCraft shows them as ordinary dimensions with their names in the text (`NAME=6 31/32"`), but `parameters {}` says "No parameters" and `constraints.dof {}` "No constraints": **constraint data in a DWG is not imported**, so you cannot re-solve it; re-create constraints with `gc…`/`dc…`/`parameters` if needed. Dimension geometry is read (`entities {"type":"Dimension"}` gives `measurement` 0.25 … 8.0 inch, `kind` linear/diameter, the dimension block name `*U0`).
- **Imperial → metric on a real part:** `entities {}` for all handles, `scale {"handles":all,"base":[0,0],"factor":25.4}`, `units {"lunits":2,"luprec":1,"insunits":4}` turned every `measurement` into the exact ×25.4 value (0.25 → 6.35, 1.0 → 25.4, 8.0 → 203.2) and the geometry rendered identically scaled; **the printed dimension text did not change** (still `6 31/32"`), because the dimension blocks keep their text: set `textOverride` through `properties.set`, or delete and redraw dimensions after scaling.
- **A dynamic ISO title block (AC1024, one insert of block `Title_Block-ISO`, 117 entities, a layout "Architectural Title Block" for ARCH D, no viewports, no attributes):** `blocks.dynamic {"name":"Title_Block-ISO"}` shows a **Visibility State** parameter with states ISO A1, A2, A3, A4; `blocks.reference {"handle":"1E98"}` lists `properties[0].choices`; `blocks.reference.set {"handle":"1E98","name":"Title Block ISO","value":"ISO A2"}` switches the state, and the exported PDFs showed four visibly different title blocks (checked in a contact sheet). The insert is anonymous (`*U2`), so find its handle with `entities {"type":"Block Reference"}`. The drawing is A1-sized (841×594) in model space.
