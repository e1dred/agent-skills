# CadCraft

Field notes from one real task (a wiring schematic), tested on **cadcraft-cli 0.13.0** (Linux AppImage). CadCraft is an AutoCAD-style 2D drafting app (441 commands, DXF/DWG in and out). The CLI, the live control channel and the MCP bridge run the same commands. VectorCraft (illustration, not CAD) was extracted too but not tested; for precise, labelled, orthogonal drawings CadCraft is the better fit.

## Keep this file growing
At the end of every CadCraft task add what you verified (render and look), fix what proved wrong, keep it general (no personal data or other people's documents), add a log line.

## Setup
- **CLI:** `~/AppImages/cadcraft.appimage --appimage-extract` (in a scratch folder), copy `squashfs-root/usr/bin/cadcraft-cli` to `~/AppImages/`. Never run `--version` on the AppImage itself (it opens the GUI); the CLI answers `--version`.
- **Live app:** `cadcraft.appimage --control PORT` (the user starts it). `cadcraft-cli mcp --connect HOST:PORT` is the MCP bridge; without MCP tools in the session use `tools/ccmcp.py` (stdio JSON-RPC client). Tools: `command_line, script, execute, list_commands, inspect_drawing, query_entities, render, find_text, new_drawing, open, save, cancel, screenshot, ui_inspect, ui_click`.
- Helper for drawing: `tools/schem.py` (a `Sheet` that collects commands, then `build()` writes DXF, a white PDF and a PNG). Example: `examples/relay_lamp.py`.

## CLI essentials (verified)
```
cadcraft-cli run [FILE | --sample | --metric] [--script TEXT] [--script-file F.scr] [--cmd 'id {json}']... [--save OUT.dxf] [--export OUT.pdf|svg|png]
cadcraft-cli info FILE.dxf                      # counts per entity type, layers, extents
cadcraft-cli convert IN.dxf OUT.(dxf|dwg|svg|png|pdf) [--window x0,y0,x1,y1 | --view extents]
cadcraft-cli commands [FILTER]                  # JSON: id, label, params string, menu (the parameter docs live here)
```
- `--cmd 'rectang {"p1":[20,20],"p2":[60,50]}'`: the id, a space, then JSON. Results print as `{"handle":"101"}`; `"{last}"` in any parameter means the last handle returned (`viewport.set {"handle":"{last}"}`).
- Use `--metric` for a new millimetre drawing. A failing command stops the run and nothing is saved.
- **Export format matters:** `--export x.png` gives a DARK CAD-themed 2400×1600 picture with hair-thin lines (fine for a quick look); **`--export x.pdf` gives a white page with real colours and lineweights**: use it for deliverables, then `gs -sDEVICE=png16m -r150 -o x.png x.pdf` for a picture. The export view is the current view if you changed it (`zoom {"mode":"window","p1":[0,0],"p2":[420,297]}`), else the drawing extents. `.svg` of a text-heavy drawing is large (9.7 MB for 112 texts).

## Commands used (parameters verified)
- `layer.new {"name","color":1|"red"|index,"lineweight":0.6 (mm),"linetype":"DASHED","current":true}` (a linetype must be loaded first: `linetype {"load":"DASHED"}` or "invalid parameters … is not loaded"); `layer.current {"name"}`; `layer.set {"name","on","frozen","locked","color",…}`. New objects take the current layer.
- Text: the default style "Standard" is a **stick font**; make a readable one first: `style {"name":"SCH","font":"Arial","height":0,"current":true}`. `text {"at":[x,y],"text","height":2.6,"justify":"L|C|R|M|TL…","rotation":90}` (justify with `C`/`R` aligns on `at`), `mtext {"at","text","width",…}`.
- Geometry: `line {"points":[[x,y],…]}`, `pline {"vertices":[…],"closed","width"}`, `circle {"center","radius"}`, `arc {"center","radius","start","end"}` (degrees), `rectang {"p1","p2"}`, `donut {"center","inside":0,"outside":2.2}` (a filled **junction dot**), `ellipse`, `spline`, `point`, `hatch`.
- Editing: `move`, `copy`, `rotate`, `mirror`, `scale {"handles","base","factor"}`, `offset`, `trim`, `fillet`, `stretch`, `array`, `explode`; blocks: `block {"name","base","handles"}` then `insert {"name","at","scale","rotation"}`, `wblock`. Dimensions: `dimlinear`, `dimaligned`, … (not used).
- Output: `export {"path","format"}`, `exportpdf {"path","paper","landscape","fit","scale"}`, `plot`.

## Drawing a schematic (what worked)
1. Plan on a sheet in mm (A3 landscape 420×297): a +V rail and a 0 V rail as long horizontal lines, parts hanging between them, signal flow left to right. Put coordinates in named constants.
2. One **layer per net or role** (supply +, return, trigger, switched, each signal colour, symbols, text, notes, "suggested" changes in dashed green): the legend and later edits (hide a layer) come for free.
3. Symbols from primitives: rectangle plus pads (circles r 1.2) for parts, a diagonal in a box for a relay coil, a line pair and a lifted arm for a switch, a triangle plus a bar for a diode, junction dots with `donut` ONLY where a branch leaves (not at corners).
4. Frame, title, legend and a "how it works" text box make the PDF self-explanatory.
5. Check at 150 dpi in crops (`gs … -r150`, then PIL `crop`): label overlap was the main problem (text near box edges, labels on wires). Keep labels ≥ 2 mm from lines; right-align (`"R"`) labels that sit left of a box.
6. 388 commands for a 1-sheet schematic ran in about a second headless.

## Checking a schematic's connections (verified)
Parse the saved ASCII DXF (LINE, small LWPOLYLINE donuts for junction dots, CIRCLE pads) and union the wire endpoints; a wire connects to another only at a shared endpoint or a junction dot. Compare the resulting nets with the written connection list, and report T-contacts without a dot and wire crossings. It confirmed a 6-switch/relay/controller drawing net by net (0 crossings). It proves the DRAWING matches the text, not that the real parts behave as described.

## Live window
- To refresh a drawing the file on disk changed: `execute {"command":"close","params":{"index":N}}` (a clean document closes without a prompt) and `open` it again; `open` alone adds a second copy.
- `open {"path":"…dxf"}` → `{entities,index,warnings}` opened the drawing as a new document next to the user's empty `Drawing1` (nothing replaced). `execute {"command":"zoom","params":{"mode":"extents"}}` → null.
- **`screenshot` answers "no frame was presented (screen locked or window hidden)" when the window is not visible**; the offscreen `ui.render` renders only the drawing, not the UI. Ask the user to unlock the screen and bring the window forward before any UI test.

## Traps
- Unknown or unloaded linetype in `layer.new` fails the whole run.
- PNG export is dark and thin: not for documents.
- Handles are strings; commands that need entities (`block`, `trim`, `hatch`) need the handles from earlier results (use `{last}` or collect them).
- Not possible or not available: authoring dynamic blocks (no commands, UI only), a second CadCraft version (0.13.0 is the latest release). Not tested: VectorCraft.

## Round 2 (2026-10-26, cadcraft-cli 0.13.0, headless, rendered and looked at)
`tools/ccrun.py`: `run([(cmd, params), …], save=, export=)` runs many commands in one `cadcraft-cli run` and returns every result as JSON (raises on the first failure).

**Handles.** Hex strings counted from `100` in creation order; a dimension, array, insert or explode may use several. Read them from the results. `{last}` used twice in one command names the SAME handle (`dimangular {"lines":["{last}","{last}"]}` fails: "two non-parallel lines"). `break`, `chamfer`, `trim`, `extend`, `explode` and `fillet` can replace or renumber entities: re-read handles afterwards (`entities {"type":"Line"}`).

**Dimensions** (all drawn and checked in a PDF): `dimlinear {"p1","p2","at","text":"30 TYP"}` (the `at` point sets the side and offset; `rotation` for skewed), `dimaligned`, `dimcontinue {"points":[…]}` / `dimbaseline` continue the LAST linear dimension (one point per extra dimension, returns several handles), `dimangular {"lines":[h1,h2],"at"}` (gave 56° for the test), `dimradius`/`dimdiameter {"handle","at"}` or `{"center","point"}` (the point must be ON the circle: the number is centre-to-point distance, mine read R8.16 for r 8). `mleader {"points":[[arrow],[bend],[landing]],"text"}`. Styles: `dimstyle {"name","DIMTXT":4,"DIMASZ":3,"DIMTXSTY":"A","current":true}`, `style {"name","font":"Arial","current":true}`; dimension text takes `DIMTXSTY`. `DIMDEC 1` did not change the printed "30" (use `units {"luprec":n}`). Unit/precision: `units {"lunits":2,"luprec":2}`; `--metric` or not decides the starting units (insunits 4 mm vs 1 in).
**Hatch and gradient:** `hatch {"points":[[x,y]]}` (internal point) or `{"handles":[closed]}` plus `pattern` (`ANSI31`, `ANSI37`…), `scale`, `angle`; islands (circles inside a rectangle) stay unhatched by default. `gradient {"handles","name":"LINEAR","color1":"red","color2":"blue"}` rendered correctly in PDF.
**Blocks and attributes:** `attdef {"tag","default","at","height"}`, then `block {"name","base","handles":[…incl. the attdef]}` (the originals become an insert, handle in `insert`), `insert {"name","at","scale","rotation","attribs":{"TAG":"v"}}`; `attedit {"handle","values":{"tag":"v"}}` (tags case-insensitive); `texts {}` lists attribute values with `tag`; `count {}` counts inserts; `insert {"explode":true}` returns the new handles; a handle that does not exist in `block` is silently dropped (an attdef missing from the block gave "unknownTags"). `wblock {"path","base","handles"}` writes a file, `insert {"name","file","at"}` defines the block from it, `import {"path","at","scale"}` brings a drawing in as loose entities, `xattach` for references (untested).
**Layouts and plotting:** `layout.new {"name":"A3","viewport":false}`, `pagesetup {"layout","paper":"A3","landscape":true}`, `layout {"option":"set","name"}` (makes it current; later commands go to paper space), `mview {"p1","p2"}` returns the viewport handle, `viewport.set {"handle","scale":"1:2","center":[x,y]}` (needs a handle when nothing is selected), `exportpdf {"path","layout":"A3"}` gives a 1190×842 pt A3 page with the viewport drawing and paper-space text; `plot {"path","layout":"Model","paper":"A4","fit":true}` for model space. `layout {"option":"list"}` shows page settings. Save a model-space drawing with `--save` (there is NO `save` command in `run`).
**Editing verified:** `trim {"handle","pick","edges":[h]}`, `extend`, `offset {"handle","distance","side"}`, `fillet {"handle":rect,"polyline":true,"radius"}` (`filleted:4`), `chamfer {"h1","p1","h2","p2","d1","d2"}`, `stretch {"window","delta"}`, `break {"handle","p1","p2"}`, `lengthen {"handle","delta","pick"}`, `align`, `mirror {"handles","p1","p2"}`, `rotate {…,"copy":true}`, `scale`, `arrayrect {"handles","rows","cols","rowSpacing","colSpacing"}` (associative: one array handle), `arraypolar` (the centre of the array must differ from the object, or the copies coincide), `divide` (puts point objects: invisible unless the point style is changed), `pedit {"option":"width"|"fit"|"close"|"join"}`, `centermark` (two lines on the CENTER linetype), `revcloud {"p1","p2"}`, `polygon`, `xline`, `group {"name","handles"}` + `groups.list`, `table {"at","rows","cols","title","header","cells"}`.
**Properties and queries:** `properties.set {"handles","layer","color":"blue"}`, `matchprop {"source","targets","properties":["layer"]}`, `qselect {"type","property","operator","value"}` and `select {"window"}` (selection lives only within one run), `entities {"type","layer","window"}`, `texts`, `list`, `dist`, `area`, `find {"find","replace"}` (MText too), `purge`, `audit`, `undo {"count":1}`, `layerstate.save/list`, `view {"option":"save|list"}`, `getvar`/`ltscale`. Layer tools take handles or names: `layiso`/`layoff`/`layfrz` need `{"handles":[…]}` of objects on the layer, `laymrg {"from":[names],"to"}`, `laydel {"names":[…]}` (deletes the objects too!).
**Linetypes:** `linetype {"load":"CENTER"}` loads from the built-in library (BORDER, CENTER, DASHED, DASHDOT, DIVIDE, DOT, HIDDEN, PHANTOM…); a `file` that does not exist fails ("acad.lin: No such file").
**Formats:** DXF → DWG → DXF round trip kept circles, lines and MText (counts equal); `convert` writes DWG. `.scr` files work: `run --script-file s.scr` with lines like `CIRCLE 0,0 10` (also `RECTANG 0,0 20,10`).
**Live bridge (port 47827, tested):** `command_line` and `script` take **`text`** (not `command`); `command_line` is one prompt answer per call (`LINE`, then `0,0`, then `40,20`, then empty to finish) and `CIRCLE 0,0 10` on one line only started the command, so for multi-token lines use `script {"text":"CIRCLE 50,50 5\nLINE 0,0 50,50\n"}`; `execute {"command","params"}` runs the JSON form (same as headless), `new_drawing {"metric":true}` adds a document without touching the user's, `query_entities`, `find_text {"text"}`, `list_commands {"filter"}`, `inspect_drawing`, `render` (image), `undo` via execute. `screenshot` still refuses when the screen is locked. Test content stays in the live window (close without saving).

## Round 4 (2026-10-26, 0.13.0, headless, text rendered and looked at)
- **Rich text (verified in PDF):** `mtext` understands MTEXT codes: `{\\fArial|b1;Bold}`, `\\C1;red\\C0;`, `\\LUnder\\l`, `\\P` (new line); `width` wraps, `list:"bullet"` bullets (one item for the whole string), `justify:"TL"`, `lineSpacing`. In `text`, `%%d` gives ° and `%%p` gives ±, but **`%%c` (diameter) showed as an empty box in Arial**: use a font that has the glyph or write the character. `textedit {"handle","text"}` also overrides a dimension's text ("100 REF"); `dimtedit.left` moves it. `txt2mtxt` needs a selection (fails "No text objects selected").
- **Export:** `convert x.dxf x.svg --view extents` (389 KB for a small text sample), `convert … x.png --window x0,y0,x1,y1`; `plot`/`exportpdf` with `scale:"1:2"`, `plotArea:"window"` + `window:[[x,y],[x,y]]`, `fit` all produced A4 pages; `pagesetup {"layout":"L","plotStyleTable":"monochrome.ctb"}` works on a layout you created (the Model tab is not a layout name for `pagesetup`).
- **Xrefs:** `xattach {"path","at"}` (returns the handle and `xref` info), `xref {}` lists status (`Loaded`, references, objects), the reference shows in `blocks.list`; `xbind {"type":"layer","names":"REF|LAYER"}` only matches symbols that depend on an xref, so a reference with no named layers/styles has nothing to bind; `xopen {"name"}`, `refedit` untested.
- **Styles:** `mleaderstyle {"name","arrowSize","textHeight","current":true}` then `mleader` uses it; `tablestyle {"name","textHeight","current":true}` and `table.cellstyle {"handle","style":"Header","row":1}` (cell styles are `Title`, `Header`, `Data`, not `_HEADER`); `scalelistedit {}` lists the scale list (1:1, 1:2, 1:4, 1:5, 1:8, 1:10…), `{"add":{"name":"1:7","ratio":"1:7"}}` adds one; `style {…,"annotative":true}`; `objectscale {"handles","add":"1:50"}`.
- **Editing and queries:** `dimbreak {"handles":[dim]}` (`changed:1`), `dimspace` (`spaced:0` with one dimension), `hatchedit {"handles":[hatch],"pattern":"ANSI37","scale":2}` and `{"gradient":{…}}` (`changed:1`), `splinedit {"handle","option":"close|polyline"}` and `fitmove` (needs `index` and `to`), `-vports {"option":"3","arrangement":"right"}` / `save` / `list` (tiles with their rectangles), `autoconstrain {"handles"}` (3 constraints added to two nearly horizontal/perpendicular lines), `parameters {"name":"W","expr":"40"}`, `ellipse {"center","major":[dx,dy],"ratio","start","end"}`, `spline {"control":[…],"degree":3}`, `wipeout`, `point.multiple`, `ray`, `donut`, `copyclip` + `pasteclip {"at"}`, `draworder.front`, `group` / `ungroup`.

## Round 5: end-to-end recipe, a metre-unit floor plan on an A3 sheet (2026-10-26, 0.13.0, rendered and looked at)
Order that worked in ONE `ccrun.run` list: load linetype, readable `style`, layers with colour and lineweight (WALL 0.5 mm, DOOR, DIM, TEXT, FRAME), `mlstyle {"name":"WALL","elements":[{"offset":0.1},{"offset":-0.1}],"current":true}`, `mline` walls (closed outline plus a partition; `justification:"zero"`, `scale:1` or the default style's ±0.5 offsets apply), a door symbol drawn once in `door.dxf` (line + arc) and placed with `insert {"name":"DOOR90","file":"door.dxf","at","scale":[-1,1]}` (a negative X scale mirrors the swing; this avoids needing handles for `block`), `text` labels, `dimstyle` and `dimlinear`, then `layout.new {"viewport":false}`, `pagesetup`, `layout set`, a `rectang` frame in paper space, `mview {"p1","p2"}`, `viewport.set {"handle":"{last}","scale":…,"center":[x,y]}`, `table`, `exportpdf {"layout"}`. Layer colours and lineweights came out right in the PDF (door green, labels yellow, walls heavier).
Traps seen: (1) **`viewport.set` scale is paper units per model unit**: in a metre drawing 1:20 is `50` (1000 mm / 20); `"1:20"` gave 0.05 and a blank sheet with a dot. A viewport's `viewHeight` in the result tells you what is shown. (2) **Model-space text and dimension heights are in model units**: with a 1:50 viewport a 0.25 m label prints 12.5 mm, far too big; make annotation height = wanted print height ÷ viewport scale (set `DIMTXT`, `DIMASZ`, `DIMEXO`, `DIMEXE` and the text heights accordingly, or use `DIMSCALE`). (3) A `table` grows DOWN from `at`: put `at` at its top-left, or the title block falls off the sheet. (4) A viewport can be re-scaled later by opening the saved DXF: `run plan.dxf --cmd 'layout {"option":"set","name":"PLAN"}' --cmd 'viewport.set {"handle":"10D","scale":50}'`, the handle is in the earlier `mview` result.

## Round 6: live window (2026-10-26, app 0.13.0 on port 47827, screen unlocked, screenshots looked at)

- **Interactive drawing by clicks works:** `command_line {"text":"LINE"}` starts the command (the prompt is in the result's `prompt`), then `ui_click {"x","y"}` in WORLD coordinates answers each point prompt (a polyline of 3 clicks, a circle centre then `command_line "8"` for the radius, a rectangle by two corners, DIMLINEAR by three clicks, OFFSET: `5`, click the object, click the side, empty line to exit). - **Selection by click:** a click on an object selects it (`ui_inspect.session.selection`, picked-first then `MOVE` worked on it), two clicks on empty space left-to-right make a window selection, a click on empty space does not clear it; ERASE with a window drag erased all four objects and `undo` restored them.

- **`ui_click` is canvas-only:** screen-space clicks on toolset icons, menus and panels did nothing useful, and `execute` with an empty `params` never opens dialogs (`options` returns the settings JSON, `plot` returns base64 PDF data, `dimstyle`/`style` demand a `name`). So panels and dialogs cannot be driven; use the JSON commands.
- Every `new_drawing` adds a tab (Drawing2…4 left open and unsaved in the user's window). `inspect_drawing` and `query_entities` read the ACTIVE document.

## Round 8 (2026-10-26, 0.13.0; annotative result looked at in a PDF)
- **Annotative text (verified):** with `style {"name":"AN","font":"Arial","annotative":true,"height":3,"current":true}`, a `text` of height 3 in a 5000×3000 model plus `objectscale {"handles":[text],"add":["1:50","1:100"]}` printed at the same 3 mm in two layout viewports at 1:50 and 1:100; the same text in a NON-annotative style was invisible (3 model units). ## Round 9: a real drawing in the live window (2026-10-26, app 0.13.0; screenshots looked at)
- `open {"path"}` loaded a 285-entity schematic as a new tab (`{entities, index, warnings:[]}`) and a screenshot after `zoom extents` showed it complete: frame, wires in net colours, symbols, text, legend.
